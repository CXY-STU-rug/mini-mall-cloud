## 2. 当前无法完成实机链路验收的原因

本机检查时以下端口未启动：

- 网关 / 后端：`9080`, `9001` ~ `9009`
- 基础设施：MySQL `3306`、Redis `6379`、Nacos `8848`、RabbitMQ `5672`、Elasticsearch `9200`、Seata `8091`
- 前端：商城 `5174`、后台 `5173`

Docker 引擎在当前环境中也未连上，所以暂时不能跑完整“注册 → 下单 → 支付 → 回调 → 退款 → 搜索同步”的实机流程。

## 3. 真正上线 / 演示前必须跑通的核心链路

### 用户与商品

- 注册用户。
- 邮箱登录。
- 浏览首页商品。
- 商品详情页能打开。
- 搜索商品能返回结果。
- 分类筛选、价格排序、销量排序正常。

### 购物车与普通订单

- 加购物车。
- 修改购物车数量。
- 选择收货地址。
- 创建普通订单。
- 创建订单后库存扣减成功。
- 取消未支付订单后库存回滚。

### 支付

- 普通订单能创建支付宝沙箱支付单。
- 前端能打开支付宝收银台。
- 支付完成后异步回调能把订单改成已支付。
- 前端支付页轮询能显示支付成功。
- 支付对账任务能兜底修复“支付单已支付但订单未支付”的情况。

注意：支付宝异步回调必须使用公网可访问地址。本地测试可用内网穿透，正式上线必须使用 HTTPS 域名。

### 退款

- 已付款订单能申请退款。
- 退款后订单状态更新。
- 退款后库存回滚。
- 如果订单使用优惠券，优惠券能退回。
- 退款远程调用失败时，要能通过日志或后续补偿发现。

### 搜索同步

- 后台新增商品后，前台搜索能查到。
- 后台编辑商品后，前台搜索内容能更新。
- 后台下架商品后，前台搜索不再展示。
- 后台删除商品后，搜索索引能删除。
- 扣库存 / 回库存后，搜索里的库存字段能同步。
- RabbitMQ 消费失败时，消息能进入死信队列。

### 秒杀

- 秒杀活动能查询。
- 秒杀库存 Redis 预热正常。
- 抢购成功后能创建普通订单。
- 同一用户重复抢购会被拦截。
- 秒杀 MQ 消费失败时能发现并处理。

### 后台

- 管理员登录。
- 商品新增 / 编辑 / 上下架 / 删除。
- 订单列表查询。
- 后台发货。
- 用户管理查询。

## 4. 上线前必须处理的安全项

- 生产环境必须设置强 `JWT_SECRET`，并保证 gateway / auth / user 使用同一个值。
- 所有数据库、Redis、RabbitMQ、MinIO、AI、支付宝密钥都必须通过环境变量或部署平台密钥管理注入。
- 不能把真实 `application.yml`、`.env`、私钥、证书提交到仓库。
- 支付宝私钥、支付宝公钥、应用 AppId 必须区分沙箱和正式环境。
- 后台管理端必须限制管理员权限，不能让普通用户访问 `/admin/**`。
- 生产环境建议关闭过多 debug 日志，避免泄露请求参数、token、支付信息。
- Nacos、RabbitMQ、MinIO、ES、Seata 控制台不能直接裸露到公网。

## 5. 当前不建议马上正式上线的原因

- 还没有跑完整实机链路。
- 支付正式环境需要商家资质、应用上线审核、HTTPS 回调域名。
- 物流目前更适合先做模拟或手工录入，正规快递轨迹需要对接服务商接口。
- 退款补库存、退券目前已有改进，但生产级还应继续做补偿表 / 重试任务 / 运维可视化。
- 搜索同步已改 MQ，但还需要实测 RabbitMQ 死信、重放和异常告警。

## 6. 推荐下一步

先把本地基础设施拉起来，再跑一轮完整链路：

1. 启动 MySQL、Redis、Nacos、RabbitMQ、Elasticsearch、Seata。
2. 导入 `sql/schema.sql`、`sql/g8-coupons.sql`、`sql/seckill_order_fix.sql` 等必要 SQL。
3. 配好各服务真实 `application.yml` 或环境变量。
4. 启动 user / product / order / review / search / auth / file / payment / gateway。
5. 启动商城前端和后台前端。
6. 按第 3 节逐项验收。

如果这一轮全部通过，再进入服务器部署、域名 HTTPS、Nginx 反代、日志监控和备份策略。
